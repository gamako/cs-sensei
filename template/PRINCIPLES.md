# 原理の索引

この学習で扱う「**学ぶこと**」——題材が入れ替わっても通じる原理——の一覧です。
`原理名 — 通じる言い方〔正典名〕` の形で書いてあります。

## 読む向き

**上から選ぶための一覧ではありません。** 決まったことに名前を付けるために引きます。

- `log/` に書く「学ぶこと」の名前を、ここから取る
- 3 回分たまって見立てを変えるとき、次の候補をここで探す

**ここに無い原理を選んではいけない、ということはありません。** 網羅ではないので、
無ければ足してください。`AGENTS.md` の「レイヤーも分野も問いません。ここに無いもので
かまいません」がそのまま生きています。

## 並びについて

**群の中は順不同です。** 隣接が意味するのは「同じ軸で分かれる」ことだけで、
学ぶ順序でも、前提の順序でもありません。上から順にやるものではありません。

`↳` の行が、そのブロックの**分かれ目（軸）**です。同じ状況に複数が当てはまるとき、
どちらを学ぶ回にするかの条件が書いてあります。`AGENTS.md` は一度に一つの原理しか
扱わないので、選ぶ必要があります。

`（〜の中の話）` と付いている項目は、直前の項目に含まれる話です。

`↝` は同じ原理が**別の層で現れる場所**です。下の層から上の層の順に並べています。

---

**計算とメモリ階層**
- 参照の局所性 — 同じデータ量でも、触る順序で速度が変わる
    ↝ キャッシュ行 / ページ / ディスクのシーク / 列指向ストレージ
- 表現のコスト — 論理的な 1 個と、物理的な 1 個は違う〔メモリレイアウト / オブジェクトオーバーヘッド〕
    ↝ ワード境界とパディング / オブジェクトヘッダ / 行のサイズ / シリアライズ形式
  ↳ 触る順序か、一個の大きさか
- 作業集合 — 収まっているうちは速く、あふれた瞬間に崩れる
    ↝ キャッシュミス / スワップ / バッファプール / コネクション枯渇
- 断片化 — 空きの合計はあるのに、使えない
    ↝ メモリ断片化 / ディスクの断片化 / ヒープの空き / クラスタの空き資源
- 置換 — 入らないとき、何を残すかで次の速度が決まる〔LRU / ページ置換〕
    ↝ キャッシュ置換 / ページ置換 / GC の世代 / CDN の退避
- 流す — 全部を持たなくて済むなら、大きさは制約ではなくなる〔ストリーム処理 / オンラインアルゴリズム〕
    ↝ DMA / パイプ / イテレータ / ストリーム処理
  ↳ 入るかどうかが作業集合、合計はあるのに使えないのが断片化、
    入らないとき何を残すかが置換、そもそも全部持たないのが流す
- 投機と取り消し — 予測が当たる限り速く、外れたときのコストが上限を決める〔投機実行 / 分岐予測〕
    ↝ 分岐予測 / プリフェッチ / 楽観ロック / 先読み
- 表現の有限性 — 数は有限桁で近似されていて、順序で誤差が変わる〔浮動小数点の丸め誤差 / オーバーフロー〕
    ↝ 2 の補数 / 浮動小数点の丸め / 桁あふれ / 通貨の計算

**状態と時間**
- 状態の寿命 — どこに置いたものが、いつまで残るか〔TTL / セッション管理（単一の正典名なし）〕
    ↝ レジスタ / プロセスのメモリ / セッション / 署名の有効期限
- キャッシュの無効化 — 古い答えが返る条件は、読む側ではなく書く側にある
    ↝ キャッシュコヒーレンス / ページキャッシュ / 中間キャッシュ / 導出データの再計算
  ↳ 消えるのか、古くなるのか
- 共有と変更 — 同じ実体を複数から指していると、片方の変更が他方に現れる〔共有可変状態 / エイリアシング〕
    ↝ ポインタの別名 / 参照渡し / 浅いコピー / 外部キー
- 冪等性 — 同じ操作を 2 回実行しても結果が変わらない条件
    ↝ 再送 / リトライ / UPSERT / 宣言的な適用
- 論理的な順序 — 時刻は順序の代わりにならない〔論理時計 / happens-before〕
    ↝ メモリバリア / 因果順序 / ベクタクロック / 版番号
- 時刻の表現 — 一意に見える時刻は、一意ではない〔タイムゾーン / うるう秒 / UTC〕
    ↝ サイクル数 / 単調増加時計 / 壁時計 / 暦
  ↳ 欲しいのが順序なら前者、時点なら後者

**並行性**
- 不可分性 — 途中の状態が他から見えると、失われる更新が起きる
    ↝ アトミック命令 / トランザクション / 楽観ロック / 分散ロック
- 検査と使用の間 — 確かめた時点と使う時点の間に、変わる〔TOCTOU〕
    ↝ 割り込み / ファイルの確認と使用 / 在庫確認と引き当て
  ↳ 失われるのが更新か、検査か
- 可換性 — 順序を入れ替えても同じなら、待たなくてよい
    ↝ 命令の並べ替え / ロック不要な更新 / 直列化可能性 / CRDT / マージ
  ↳ 可換なら不可分性は要らない。順序を守る必要があるかどうかが手前の問い
- 資源の順序 — 待ちの輪ができる条件〔デッドロック / ロック順序〕
    ↝ ロック順序 / ラッチの獲得順 / 分散ロックの獲得順
- 直列部分の支配 — 並列化できない部分が上限を決める〔アムダールの法則〕
    ↝ パイプラインのハザード / クリティカルセクション / 集約処理

**負荷と競合**
- 待ち行列 — 利用率が上がると待ち時間は線形には増えない〔待ち行列理論〕
    ↝ バス調停 / ディスク I/O / スレッドプール / リクエスト処理
- スケジューリング — 誰を先にやるかで、平均も公平性も変わる（待ち行列の中の話）
    ↝ 命令の発行順 / プロセススケジューラ / I/O の並べ替え / ジョブの優先度
- ポーリングと割り込み — 聞きに行くか、呼んでもらうか
    ↝ プログラム I/O と割り込み駆動 / busy-wait と待機 / 定期取得と通知 / pull と push
- バックプレッシャー — 生産と消費の速度差は、どこかに溜まる
    ↝ フロー制御 / 有界キュー / ストリームの一時停止
  ↳ pull なら自然に背圧がかかる。push だと伝える仕組みを別に用意する
- 捨てる — 全部を受けると全部が失敗する。捨てれば残りは通る〔ロードシェディング〕
    ↝ パケット破棄 / キュー溢れ / レート制限 / 優先度による切り捨て
  ↳ 分かれ目は「生産側を止められるか」。止められないならバックプレッシャーは使えない
- 共有資源の奪い合い — 各自が最適に振る舞うと、全体が悪くなる〔輻輳崩壊 / コモンズの悲劇〕
    ↝ バスの飽和 / 輻輳崩壊 / コネクション枯渇 / リトライストーム
- 散らす — 同時に集中するものは、ずらせば減る〔ランダムバックオフ / ジッタ〕
    ↝ 衝突後のバックオフ / ハッシュ分散 / TTL のずらし / 実行時刻の分散
  ↳ 前者が問題、後者が解法。散らす側だけで 1 回分になるので別に立てている
- 事前確保 — 資源を先に確保するか、その都度取りに行くか〔回線交換とパケット交換 / 資源予約〕
    ↝ レジスタ割り当て / メモリの事前確保 / コネクションプール / 帯域予約
  ↳ 奪い合いの手前。予約すれば競合は起きないが、使われない資源が出る

**永続化とトランザクション**
- 耐久性と書き込み順序 — 「書いた」がどの時点を指すか
    ↝ ライトバッファ / fsync / ジャーナル / レプリカへの確認
- クラッシュ復旧 — 壊れないのではなく、直せる形で壊す
    ↝ ECC / ジャーナリング / 先行書き込み / スナップショットと再生
  ↳ 壊れないようにするか、直せるようにするか
- トランザクション分離 — 何が見えないことを保証しているか
    ↝ メモリ一貫性モデル / 分離レベル / スナップショット
- 選択性 — 索引が効くのは、絞れるときだけ
    ↝ 索引 / 分割 / ブルームフィルタ / 検索の絞り込み

**通信**
- 帯域とレイテンシ — 太くしても、近くはならない
    ↝ バス幅とアクセス時間 / 転送とシーク / 往復時間 / API の呼び出し回数
- 名前と束縛 — 名前が何を指すかは、いつ、どこで決まるか
    ↝ シンボル解決 / 変数のスコープ / 名前解決 / サービス発見
- 名前空間の階層 — 階層にすると、覚える量が減る〔経路集約 / CIDR〕
    ↝ アドレスの上位ビット / ファイルパス / 経路集約 / ドメイン
  ↳ 何を指すかか、名前空間の形が表の大きさを決めるか

**分散**
- 部分故障 — 失敗と遅延は受け手から区別できない
    ↝ デバイスの無応答 / プロセスの停止 / ノード障害 / 依存サービスの不通
- 運命の共有 — 状態は、それが失われて困る当人と同じ場所に置く〔fate-sharing〕
    ↝ プロセスと共に消える資源 / セッションアフィニティ / 状態を持たないサーバ
  ↳ 相手の状態が分からないことが前者、だから状態をどこに置くかが後者
- 冗長と沈黙 — 壊れても動き続けるので、壊れたことに気づかない〔サイレント障害 / 故障のマスキング〕
    ↝ ECC の訂正 / RAID の片肺 / フェイルオーバ / キャッシュへのフォールバック
- 可用性の掛け算 — 直列につないだ分だけ、全体は下がる〔稼働率 / MTBF・MTTR〕
    ↝ 部品の故障率 / 直列な依存 / SLA の掛け算
  ↳ 直列にすると下がり、並列にすると上がる。並列の代償が沈黙
- 配送保証 — 届いたか・重複していないか・順番どおりか、どれを保証するか
    ↝ 再送と重複 / メッセージキュー / イベントの順序
- 一貫性モデル — 読めた値が最新とは限らない
    ↝ メモリ一貫性モデル / キャッシュコヒーレンス / レプリカの読み取り
- 合意 — 全員が同じ結論に至るには、何が要るか〔コンセンサス〕
    ↝ バス調停 / 分散ロック / リーダー選出
- 収束 — 各自が少しずつ近づけると、指揮者なしで全体が揃う〔結果整合性 / 自己安定化〕
    ↝ 経路表の学習 / ゴシップ / 宣言的な適用の収束
  ↳ いま全員一致が要るなら合意、いずれ揃えばよいなら収束。一貫性モデルは「何が見えるか」の規定で、この 2 つは「どう揃えるか」

**情報と符号化**
- エントロピー — 縮む量はデータの偏りが決めている
- 誤り検出 — チェックサムが見逃す壊れ方がある
    ↝ パリティ / チェックサム / ハッシュによる照合
- 複製と再試行 — 同じものを余分に持つか、後でやり直すか〔空間的冗長と時間的冗長 / ARQ と FEC〕
    ↝ ECC / RAID / 再送 / レプリカ
  ↳ 見つけるだけか、直すところまでか
- フレーミング — 連続した列のどこで切るかは、送る前に決まっている
    ↝ 命令長 / パケット境界 / レコード区切り / メッセージ境界
- 文字の単位 — 1 文字は、1 バイトでも 1 コードポイントでもない〔書記素クラスタ / 正規化〕
    ↝ バイトとワード / コードポイント / 書記素クラスタ
- 表現と解釈 — ビット列は意味を持たない。読み方は外から与える〔エンディアン / スキーマ〕
    ↝ エンディアン / 型としての解釈 / 文字コード / スキーマ
  ↳ どこで切るかがフレーミング、何個と数えるかが文字の単位、切った後どう読むかが表現と解釈
- 標本化 — 取りこぼした間に何が起きたかは、後から復元できない〔標本化定理 / エイリアシング〕
    ↝ クロック / プロファイラの割り込み / 監視の取得間隔 / ログの間引き
- 偽陽性と偽陰性 — どちらを許すかで、必要な資源が桁で変わる
    ↝ 分岐予測の誤り / ブルームフィルタ / 検査とアラート

**信頼と権限**
- 信頼境界 — どこから先を信用しないかを決めないと、検査する場所が決まらない
    ↝ 特権モード / プロセス分離 / 入力の検査点 / 外部連携
- データと命令の分離 — 混ざると、データが命令になる〔インジェクション / 無害化〕
    ↝ 命令もデータである（フォン・ノイマン）/ 実行可能ビット / インジェクション
  ↳ 検査する場所の決め方が前者、混ざったときに何が起きるかが後者
- 認証と認可 — 誰かという問いと、何をしてよいかという問いは別
    ↝ 特権レベル / 所有と権限 / トークン
- 混同代理 — 権限のある者が、他人の意図で動かされる〔confused deputy〕
    ↝ DMA の悪用 / setuid / CSRF と SSRF
  ↳ 権限を持つのは誰かが前者、その権限が誰の意図で使われるかが後者
- 既定の向き — 決めていないことを、許すか拒むか〔フェイルセーフ既定 / 許可リストと拒否リスト〕
    ↝ 未定義の状態 / 既定の権限 / 許可リストと拒否リスト
- 最小権限 — 被害の上限は、与えた権限で決まる
    ↝ 保護リング / プロセス権限 / 資格情報の範囲
  ↳ 書いていない場合どうなるかが前者、書いた場合どれだけ与えるかが後者
- 秘密は鍵だけ — 隠すべきは仕組みではなく鍵〔ケルクホフスの原理〕
- 一方向性 — 戻せない計算があるから、秘密を渡さずに確かめられる
- サイドチャネル — 秘密は、正解以外の経路からも漏れる
    ↝ 実行時間の差 / キャッシュのタイミング / エラーメッセージの差
  ↳ 何を隠すかが 1 つめ、なぜ隠せるかが 2 つめ、どこから漏れるかが 3 つめ

**アルゴリズムと計算量**
- 漸近と定数 — 交差点より手前では、遅いはずの方が速い
    ↝ 定数倍とキャッシュ効率 / データ構造の選択 / 索引の有無
- 償却 — ならした速さは、最悪の一回を隠す
- 最悪計算量 — 入力を選べる相手がいると、平均は保証にならない
  ↳ 入力サイズで見るか、ならした一回で見るか、選ばれた最悪で見るか
- まとめる — 固定費は分割できる。代償は、最初の一件が待つこと〔バッチ処理〕
    ↝ キャッシュ行 / バッファリング / グループコミット / バッチ処理
- パイプライン — 段に分けて重ねると、1 件あたりは遅くなるが処理量は上がる
    ↝ 命令パイプライン / 段に分けた処理 / ストリーム処理 / 段階に分けた自動化
  ↳ まとめるは固定費を頭数で割る、パイプラインは段を重ねて空きを埋める。
    どちらもスループットを上げ、1 件目の待ち時間を払う
- 速い道と遅い道 — よくある場合だけ速くすれば、全体が速くなる〔ファストパス〕
    ↝ キャッシュのヒットとミス / 例外経路 / インライン化 / 一般路と高速路
- 枝刈り — 全部見ないで済ませられる条件は何か〔分枝限定法〕
- 局所最適 — 良くなり続けても、最良には着かない
  ↳ 枝刈りは答えが変わらない、局所最適は答えが変わる

**実行環境と言語処理系**
- 到達可能性 — 生きているの定義は「使う」ではなく「辿れる」
- 資源の所有 — いつ解放してよいかを、誰が知っているか〔所有権 / ライフタイム / RAII〕
    ↝ スタックの自動解放 / 手動の確保と解放 / ファイル記述子 / コネクション
  ↳ 処理系が辿って決めるか、書いた人が決めるか
- 仮想化 — 見えているものは本物ではない。間に誰かがいる
    ↝ アドレス変換 / ファイル記述子 / コンテナ / 差し替え可能な依存
- 抽象化のコスト — 消えるものと残るものがある〔抽象化ペナルティ / ゼロコスト抽象化〕
    ↝ 関数呼び出しの分 / 動的ディスパッチ / 層をまたぐ変換
  ↳ 間に入って差し替える機構が前者、その層を通す代償が後者
- 評価戦略 — いつ計算するかで、何が起きるかが変わる
    ↝ 命令の実行順 / 短絡評価 / 遅延評価 / ビューの実体化
- 型システム — 早く失敗するか、遅く失敗するかを選んでいる
    ↝ 機械語には型が無い / 静的検査 / スキーマ検証
  ↳ 実行の時点をずらすのが前者、検査の時点をずらすのが後者

**テストと評価の設計**
- 試験可能性 — 検査できるかどうかは、書いた後では決まらない〔テスタビリティ〕
- 計測 — どこで時間が使われているかは、測らないと分からない
    ↝ サイクル数 / プロファイラ / 分散トレース
- 観測のコスト — 測る行為が対象を変える〔プローブ効果 / 観測者効果〕
    ↝ 計測命令の追加 / プロファイラの負荷 / ログ出力の負荷
  ↳ 観測点があるかが設計時（試験可能性）、観測が対象を変えるかが実行時（観測のコスト）
- ばらつき — 一回の計測は数字ではない
- 再現性 — 同じ条件なら同じことが起きる、その条件は何か
- 汎化 — 手元で当たることと、次に当たることは別
    ↝ 手元と本番 / 訓練と評価 / ベンチマークと実負荷
  ↳ 同じ条件なら同じかが前者、違う条件でも通じるかが後者。裏表
- 同値分割と境界 — 入力は同じ扱いの組に分けられ、間違いはその境目に集まる
    ↝ 桁あふれの境目 / 空と 1 件と最大 / 期間の端
  ↳ 標本化（情報と符号化）と対。同値分割は分け方が正しければ見逃さない、標本化は必ず見逃す
- テストオラクル — 何と比べて「正しい」と言っているか
- 基準線 — 「良い」は、何かと比べたときにだけ言える〔ベースライン〕
- 指標の腐敗 — 指標にした瞬間、指標が目的になる〔グッドハートの法則〕
  ↳ 比べる相手を用意するのが基準線、その基準を目標に据えると壊れるのが指標の腐敗

**設計**
- 結合 — 変更が伝わる経路は、呼び出し関係とは限らない
    ↝ 共有メモリ / モジュール間の依存 / サービス間の依存
- 情報隠蔽 — 変わりそうなものを、境界の内側に置く
    ↝ ISA が実装を隠す / モジュールの内部 / API の裏側
- 方針と機構の分離 — 何をするかと、どうやるかを分ける
    ↝ 機構と置換ポリシー / 差し替え可能な戦略 / 設定と実装
  ↳ 変更がどこへ伝わるかが結合（現象）、何を隠すと伝わらないかが情報隠蔽（手）、
    隠さず差し替えられるようにするのが方針と機構の分離
- 砂時計モデル — 中央を細くすると、両側は独立に増やせる〔narrow waist〕
    ↝ ISA / システムコール / IP / HTTP
- 漏れる抽象 — 下の層の性質は、上の層に現れる〔漏れのある抽象化〕
    ↝ キャッシュが速度に出る / 仮想記憶とスワップ / 生成されたクエリ
- エンドツーエンド — 両端で確かめるなら、途中の保証は最適化にしかならない〔エンドツーエンド原則〕
    ↝ 誤り検査をどの層でやるか / 再送の責任 / 入力検査の位置
  ↳ 中央を細くするのが砂時計、中央に機能を置かないのがエンドツーエンド、
    それでも下が透けるのが漏れる抽象
- 不変条件 — 常に成り立つ関係を、どこで守るか
    ↝ ハードウェアの保証 / 型による保証 / 制約 / 検査の位置
- 同一性 — 何をもって「同じもの」とみなすか〔同一性と等価性〕
    ↝ アドレスと値 / 等価性の定義 / 主キー / 名寄せ

**変更と運用**
- 互換性 — 約束したのは形か、意味か
    ↝ ISA の後方互換 / ABI / API の版 / スキーマ進化
- 頑健性原則 — 送るときは厳密に、受けるときは寛容に。その代償は何か〔ポステルの法則〕
    ↝ 未定義動作を許す実装 / 寛容なパーサ / 省略可能な項目
- 仕様と実装 — 動いたことは、仕様がそう決めていることを意味しない〔未定義動作 / 処理系定義〕
  ↳ 約束をどう変えるかが互換性、約束外をどう扱うかが頑健性原則、
    寛容な受信が実装への依存を育てた結果が仕様と実装
- 依存の輪 — 直す手段が、壊れたものに依存していないか〔循環依存 / ブートストラップ問題〕
    ↝ ブート順序 / 監視が監視対象に乗る / 復旧経路の依存
  ↳ 資源の順序（並行性）と別。あちらは実行中に互いを待つ輪でロック順序を揃えれば消える。
    こちらは復旧の手段が対象に依存する輪で、別経路を用意しないと消えない
- 影響半径 — 変更が一度に届く範囲が、失敗したときの損害を決める〔blast radius / 段階的展開〕
  ↳ 戻れるかが依存の輪、どこまで壊れるかが影響半径
